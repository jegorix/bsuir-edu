В VS Code нет встроенной функции «одной кнопкой» для языка C, но это можно сделать с помощью расширений. Самый эффективный способ — использовать связку Doxygen (для анализа кода) и Graphviz (для отрисовки).
## Способ 1: Автоматическая генерация через Doxygen и Graphviz
Этот метод позволяет извлечь структуру данных (struct) и связи файлов автоматически.

   1. Установите инструменты:
   * Скачайте и установите [Graphviz](https://graphviz.org/download/).
      * Скачайте и установите [Doxygen](https://www.doxygen.nl/download.html).
   2. Настройте расширение в VS Code:
   * Установите расширение Doxygen Documentation Generator.
   3. Создайте конфигурацию:
   * Запустите doxywizard (идет в комплекте с Doxygen).
      * В разделе Wizard -> Diagrams выберите «Use dot tool from Graphviz» и отметьте «Class diagram».
      * В разделе Expert -> Dot убедитесь, что путь к dot.exe указан верно, и включите UML_LOOK = YES для классического вида UML.
   4. Запуск: После генерации Doxygen создаст HTML-отчет, в котором для каждой структуры будет готова визуальная диаграмма связей. [1, 2, 3, 4] 

## Способ 2: Ручное описание через PlantUML
Если вам нужна аккуратная архитектурная диаграмма, лучше использовать PlantUML.

   1. Установите расширение: Найдите и установите PlantUML в VS Code.
   2. Создайте файл: Создайте новый файл с расширением .puml.
   3. Опишите структуру: Используйте простой синтаксис (например, struct User { ... }).
   4. Выгрузка:
   * Нажмите Alt + D для предпросмотра.
      * Кликните правой кнопкой мыши по окну предпросмотра и выберите Export Current Diagram.
      * Выберите формат: PNG, SVG или PDF. [5, 6, 7, 8, 9, 10, 11] 
   
## Способ 3: Визуализация «на лету» (Extension)
Для быстрого анализа текущего кода можно использовать расширения вроде Auto-UML или C++ Class Diagram (многие из них поддерживают C-структуры). Они добавляют кнопку «Show Diagram» в контекстное меню файла или заголовка структуры.
Совет: Для больших проектов на C лучше всего работает Doxygen, так как он автоматически отслеживает include и зависимости между файлами без ручного переписывания кода в UML-нотацию. [2]
